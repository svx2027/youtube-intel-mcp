What this proves: the server's HTTP transport performs a real MCP session
(initialize -> list_tools -> call_tool -> session teardown) over actual
sockets on 127.0.0.1, matching the request sequence the Streamable HTTP spec
defines (session-scoped POSTs, a GET for the server-initiated stream, and a
final DELETE to terminate the session) -- not a mock, and not the stdio path
exercised by this repo's existing tests/test_server.py.
